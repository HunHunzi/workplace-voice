# 职场最佳嘴替

![职场最佳嘴替图标](./icons/icon-128.png)

一个用于整理中文工作消息的 Chrome / Edge 扩展。输入口语化草稿后，可以将其整理为自然、简洁、可直接发送的工作消息。

支持独立整理台、飞书网页版和 Lark 网页版；默认调用阿里云百炼，也可以切换到 OpenAI 或其他兼容 OpenAI Chat Completions 协议的服务。

> 本项目不是飞书或 Lark 官方插件，与飞书、Lark、阿里云及 OpenAI 不存在隶属或合作关系。

## 功能

- 整理口语化、重复或缺少结构的工作消息。
- 保留事实、数字、时间、链接、人名、责任人和原文语气。
- 根据内容选择自然段落或分点，不强制套用固定模板。
- 在飞书聊天框内使用 `⌘ Enter` 整理并回填消息。
- 提供独立整理台，可复制结果到邮件、文档或其他聊天工具。
- 支持阿里云百炼、OpenAI 和自定义兼容接口。
- 支持可选的“大厂黑话版”和自定义补充要求。
- 不保存整理台中的原始内容和整理结果。

## 使用要求

- Chrome、Microsoft Edge 或其他支持 Manifest V3 的 Chromium 浏览器。
- 至少一个受支持服务的 API Key。
- 飞书快捷键目前使用 macOS 的 `⌘ Enter`；其他系统可以使用独立整理台。

## 安装

目前项目以未打包扩展的方式安装：

1. 下载源码并解压。
2. 在 Chrome 地址栏打开 `chrome://extensions/`；Edge 打开 `edge://extensions/`。
3. 开启页面右上角的“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择包含 `manifest.json` 的项目目录。
6. 首次安装会自动打开设置页，选择 API 服务并填写配置。
7. 使用飞书功能前，刷新已经打开的飞书或 Lark 页面。

更新源码后，需要在扩展管理页点击“重新加载”，并再次刷新飞书页面。

## API 配置

打开扩展弹窗并点击“设置”，选择需要使用的 API 服务。

| 服务 | 默认模型 | 默认 Base URL | 说明 |
| --- | --- | --- | --- |
| 阿里云百炼 | `qwen-flash` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 默认选项 |
| OpenAI | `gpt-5.6-luna` | `https://api.openai.com/v1` | 使用官方 Chat Completions 接口 |
| 自定义兼容接口 | 自行填写 | 自行填写 | 必须使用 HTTPS 并兼容 OpenAI Chat Completions |

每个服务的 API Key、模型和 Base URL 分别保存，切换服务不会覆盖其他服务的配置。

配置完成后，可以点击“测试配置”。扩展会发送一段固定的虚构文本，用于检查 API Key、模型和网络是否可用。

### 自定义接口要求

自定义服务需要满足以下条件：

- Base URL 使用不包含账号信息的 HTTPS 地址。
- 接受 `POST {Base URL}/chat/completions` 请求。
- 使用 `Authorization: Bearer <API_KEY>` 请求头。
- 接受 `model`、`messages` 和 `stream: false` 参数。
- 返回 OpenAI Chat Completions 风格的 `choices[].message.content`。

保存自定义接口时，浏览器会请求访问该 API 域名。扩展只申请当前填写域名的访问权限。

## 独立整理台

独立整理台不依赖飞书，可以用于任何工作消息：

1. 点击浏览器工具栏中的扩展图标。
2. 点击“打开整理台”。
3. 在左侧输入原始内容。
4. 点击“整理内容”，或按 `⌘ Enter`。
5. 在右侧检查结果，点击“复制结果”。

单次输入最多 `12,000` 个字符。输入和输出只存在于当前整理台页面，关闭页面后不会保留。

## 在飞书中使用

扩展只在飞书或 Lark URL 路径包含 `/messenger/` 的聊天页面中响应快捷键，不会处理飞书文档内容。

1. 在聊天输入框中写下草稿。
2. 按一次 `⌘ Enter`。
3. 等待扩展整理内容并回填到输入框。
4. 检查结果，可以直接继续修改。
5. 再按一次 `⌘ Enter` 确认发送。

整理完成状态会保留 5 分钟。超过 5 分钟后再次按快捷键，扩展会重新整理当前内容。

弹窗顶部的开关只控制飞书快捷键，不影响独立整理台。

## 整理模式

### 默认模式

默认模式以自然工作对话为目标：

- 保留原文的沟通对象、语气和确定性程度。
- 结论、请求或下一步可以前置，但不自动添加“结论、需确认、待办”等标签。
- 默认使用自然短段落；确实需要扫读时才分点。
- 长内容包含三个以上独立事项时，优先使用自然引导句加短横线分点，公共排期和风险可以单独成段。
- 编号只用于有先后顺序的步骤、优先级或明确序号。
- 删除重复和冗长铺垫，不套用“说明如下、分工建议如下”等固定模板。
- 整理结果原则上不长于原文，不把短消息扩写成报告。
- 压缩时保留原定时间、调整条件、例外和影响范围，不用单个示例代替完整信息。
- 责任人、动作和截止时间放在一起；链接单独占一行。
- 英文名使用完整名字加“老师”，中文名保留名字的一至两个字加“老师”。

### 大厂黑话版

在扩展弹窗或设置页开启“大厂黑话版”后，扩展会在保留原意的前提下，将口语匹配为“颗粒度、输入、给到、对齐、拉通、抓手、卡点、闭环、复盘、沉淀”等表达。

该模式只转换表达方式，不会主动增加流程、参与方、目标、指标、责任人、承诺或时间。

### 补充要求

设置页中的“补充要求”会附加到默认规则之后，可以用于指定团队内部习惯，例如：

```text
称呼保留原样；链接单独占一行；涉及日期时明确写出时间。
```

补充要求会影响所有整理入口。请避免加入与基础规则冲突或要求模型忽略安全限制的内容。

## 数据与隐私

- 只有在用户主动点击整理或按下快捷键时，消息内容才会发送给当前选择的 API 服务。
- API Key 使用 `chrome.storage.local` 保存在当前浏览器配置中，不写入项目文件，也不会通过 Chrome Sync 同步。
- `chrome.storage.local` 不是独立的加密密码库；能够访问本机浏览器配置或扩展上下文的人仍可能读取这些数据。
- 独立整理台不会把输入和输出写入浏览器存储。
- 自定义接口必须使用 HTTPS。
- 项目不会在日志、源码或示例中写入真实 API Key。

个人使用可以直接在扩展中保存 Key。团队分发或公开部署时，建议通过自有后端代理调用模型，不要在多人环境中共享同一个 API Key。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存开关、整理模式和 API 配置 |
| 阿里云及 OpenAI 域名访问权限 | 向当前选择的官方 API 发送整理请求 |
| 可选 HTTPS 域名权限 | 使用自定义兼容接口时，按域名单独授权 |
| 飞书及 Lark 页面访问 | 识别聊天输入框、回填整理结果和处理快捷键 |

## 常见问题

### 按下快捷键没有反应

确认当前页面是飞书或 Lark 的聊天页面，URL 路径包含 `/messenger/`；检查弹窗中的飞书快捷键开关，并在重新加载扩展后刷新页面。

### 提示“扩展后台连接失败”

在扩展管理页重新加载扩展，然后刷新整理台或飞书页面。

### 提示需要填写 API Key

打开设置页，确认当前选择的服务已经填写 API Key。不同服务的 Key 分别保存，切换服务后需要配置对应的 Key。

### 自定义接口无法保存或调用

确认 Base URL 使用 HTTPS，并允许浏览器访问该域名。接口还需要兼容 OpenAI Chat Completions 请求和响应格式。

### 输出仍然不符合团队习惯

检查“大厂黑话版”是否处于预期状态，并在设置页的“补充要求”中添加简短、明确、互不冲突的规则。

### 飞书页面更新后无法识别输入框

飞书网页结构变化可能影响输入框识别。请先刷新页面并确认扩展已重新加载；如果问题持续，可以提交问题并附上页面路径、浏览器版本和复现步骤，请勿附带真实聊天内容或 API Key。

## 本地开发

项目不依赖构建工具，浏览器可以直接加载源码。运行测试需要安装 Node.js。

```bash
npm test
```

主要文件：

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | Manifest V3 扩展清单与权限配置 |
| `organizer-core.js` | 提示词、服务配置、请求和响应处理 |
| `service-worker.js` | 设置迁移、API 调用和消息分发 |
| `content.js` | 飞书输入框识别、快捷键和内容回填 |
| `workspace.html` / `workspace.js` | 独立整理台 |
| `options.html` / `options.js` | API 与整理风格设置 |
| `popup.html` / `popup.js` | 扩展弹窗和快捷开关 |
| `tests/organizer-core.test.js` | 核心逻辑单元测试 |

修改代码后的验证流程：

1. 运行 `npm test`。
2. 打开扩展管理页并重新加载扩展。
3. 刷新飞书页面。
4. 分别验证独立整理台、飞书快捷键和当前 API 服务。
